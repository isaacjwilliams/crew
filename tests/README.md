# Tests

```bash
tests/run.sh                  # everything
tests/run.sh guard crew-e2e   # just these suites
KEEP_TEST_TMP=1 tests/run.sh  # keep sandboxes in tests/.tmp/ for debugging
```

Requires Linux, Go (each suite builds `crew` from this checkout), bash, git, jq, and flock, setsid and script from util-linux. shellcheck, fish and claude are optional; `lint` skips the checks that need them.

The suites run only on Linux: they use GNU and util-linux tools (`sed -i`, `stat -c`, `flock`, `setsid`, `script -qc`), and the stub `claude` reads `/proc`. On macOS, `go test ./...` runs in the release workflow (`.github/workflows/release.yml`), covering the logic both systems share; the rest is the Mac's live checks in `ARCHITECTURE.md`.

## How isolation works (`lib.sh`)

- `release_binary VERSION` builds `crew` from this checkout, stamped with VERSION, into `$CREW_TEST_RELEASES/v<VERSION>/crew-<os>-<arch>`, where the stub `curl` serves it from. Each suite builds the one for `VERSION` when it starts.
- `make_home DIR` builds a crew home the way a clone would be once it has run: the working files of this checkout, uncommitted changes included, committed to a new repo, with that binary in its `bin/release/`.
- Each suite creates sandboxes under `tests/.tmp/` and deletes them on exit. They're kept out of `/tmp` because the guard always allows writes under `/tmp`, which would hide write-guard failures.
- `isolate_home` sets `HOME` to the sandbox, gives git a throwaway identity, clears `CREW_HOME` and `CLAUDE_PROJECT_DIR`, and puts `tests/stubs/` first on `PATH`. It refuses to run if the stub `claude`, `gh`, `wt`, `curl` or `codex` isn't the one that resolves.
- The stubs:
  - `stubs/claude` logs every call to `$HOME/claude-calls.log`, and the directory the latest call ran in to `$HOME/claude.cwd`. It fakes `--bg`, printing `backgrounded · <id>` with the ID in color, and `agents --json`. A fresh `--bg` appends a job to `$HOME/agents.json` with `status` busy (`claude stop` clears it), whose ID is the first 8 characters of its session ID. Like the real CLI, `--resume <session> --bg <prompt>` continues that session in place, but starts a copy under a new session and prints a `note:` if any other launch flag is passed (`--agent`, `--settings`, …) or the session's process is still open (`pid` set). `claude stop` clears the `pid`; touch `$HOME/stop-noop` to make it do nothing. `claude rm` deletes the job; touch `$HOME/rm-fail` to make it fail. It fails the call if `--add-dir` or `--mcp-config` would swallow the prompt, and records `LEAK CLAUDECODE` if `crew` forgot to strip that variable, or `LEAK LOCK FD <n>` if its fd n is open on one of crew's `.crew*.lock` files. Touch `$HOME/fail-resume` to make `--resume` fail, `$HOME/fail-resume-late` to make it start a job that ends `failed`, or `$HOME/placeholder-session` to make the next `claude agents` after a resume show that job under a new session ID. Write `INT` or `HUP` to `$HOME/claude-interrupt` to make a bare `claude` send that signal to its process group, as Ctrl+C or a closed terminal does. The latest `--settings` value goes to `$HOME/claude-settings.last`, and every call again to `$HOME/claude-env.log`, after the `CREW_PROJECT` it ran with.
  - `stubs/wt` fakes Worktrunk's `switch` and `remove` the way `crew` calls them: it makes real git worktrees, stands in for pre-start and pre-remove hooks (`$HOME/wt-hooks.log`), and logs calls to `$HOME/wt-calls.log`. Touch `$HOME/wt-unapproved`, `wt-elsewhere` or `wt-hook-fail` to simulate unapproved hooks, a branch checked out elsewhere, or a failing hook. Write a script to `$HOME/wt-hook-cmd` and both stand-in hooks run it.
  - `stubs/gh` serves one fake PR (#12) with a fixed set of reviews, inline and conversation comments; the IDs are documented in the file. Looking up an unknown comment or review fails like a 404, and the body of the latest post goes to `$HOME/gh-last-body`. Each automated-review summary posted is listed from then on, as comment 120, then 121 and on, with its body in `$HOME/gh-summaries/<id>`, which an edit to that comment replaces. `$HOME/gh-more-comments`, when it exists, adds conversation comments, one JSON object a line. Every PR reads as merged unless `$HOME/gh-pr-state` names another state (`OPEN`). `repo create NAME --private --source . --remote origin` makes a bare repo at `$HOME/remotes/NAME.git` and adds it as `origin`.
  - `stubs/codex` fakes `codex login status` (touch `$HOME/codex-signed-out` to make it fail) and `codex exec`: it logs each call's arguments and directory to `$HOME/codex-calls.log`, its stdin to `$HOME/codex-stdin.last` prints a few events and writes `stub review` to its `-o` file. Touch `$HOME/codex-fail` to make `exec` exit 3. It records `LEAK CLAUDECODE` if `crew` left that variable set.
  - `stubs/curl` serves the release downloads `bin/crew` asks for from `$CREW_TEST_RELEASES`, and fails like a 404 for anything else. It logs every call to `$HOME/curl-calls.log`.
  - `stubs/systemctl` logs every call to `$HOME/systemctl-calls.log`, so the tests never touch your real user systemd. `enable` adds units to `$HOME/systemctl-enabled`, which `is-enabled` reads, and `show UNIT -p Environment --value` prints the `Environment=` settings of the installed unit and its drop-ins.

## Adding tests

- Every bug fix gets a case that fails without the fix. Every behaviour change updates the relevant table.
- Logic with many cases (front matter, settings files, the guard's table, resolution) is tested in Go, in `cmd/crew/*_test.go`, which `lint` runs with `go test ./...`. The suites test `crew` from outside.
- Use `check "description" 'bash expression'`. The expression is `eval`'d, so single-quote it, and add `# shellcheck disable=SC2034` for variables that only appear inside checks.
- Don't pipe into `grep -q` inside a check while `pipefail` is on: the writer gets SIGPIPE and the check fails. Capture the output into a variable first.
- Never call the real `claude` for a model session, and never point a test at your real `HOME`.
- Check that a new test can fail: break the code briefly and watch it go red.
