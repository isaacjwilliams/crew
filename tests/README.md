# Tests

```bash
tests/run.sh                  # everything
tests/run.sh guard crew-e2e   # just these suites
KEEP_TEST_TMP=1 tests/run.sh  # keep sandboxes in tests/.tmp/ for debugging
```

Requires bash, git, jq, and flock, setsid and script from util-linux. shellcheck, fish and claude are optional; `lint` skips the checks that need them.

## How isolation works (`lib.sh`)

- `make_home DIR` builds a crew home the way a clone would be: the working files of this checkout, uncommitted changes included, committed to a new repo.
- Each suite creates sandboxes under `tests/.tmp/` and deletes them on exit. They're kept out of `/tmp` because `crew-guard` always allows writes under `/tmp`, which would hide write-guard failures.
- `isolate_home` sets `HOME` to the sandbox, gives git a throwaway identity, clears `CREW_HOME` and `CLAUDE_PROJECT_DIR`, and puts `tests/stubs/` first on `PATH`. It refuses to run if the stub `claude`, `gh` or `wt` isn't the one that resolves.
- The stubs:
  - `stubs/claude` logs every call to `$HOME/claude-calls.log`, and the directory `claude remote-control` ran in to `$HOME/remote-control.cwd`. It fakes `--bg`, printing `backgrounded · <id>` with the ID in color, and `agents --json`. A fresh `--bg` appends a job to `$HOME/agents.json` with `status` busy (`claude stop` clears it), whose ID is the first 8 characters of its session ID. Like the real CLI, `--resume <session> --bg <prompt>` continues that session in place, but starts a copy under a new session and prints a `note:` if any other launch flag is passed (`--agent`, `--settings`, …) or the session's process is still open (`pid` set). `claude stop` clears the `pid`; touch `$HOME/stop-noop` to make it do nothing. `claude rm` deletes the job; touch `$HOME/rm-fail` to make it fail. It fails the call if `--add-dir` would swallow the prompt, and records `LEAK CLAUDECODE` if `crew` forgot to strip that variable, or `LEAK LOCK FD <n>` if it inherited one of crew's lock fds (7, 8 or 9). Touch `$HOME/fail-resume` to make `--resume` fail, `$HOME/fail-resume-late` to make it start a job that ends `failed`, or `$HOME/placeholder-session` to make the next `claude agents` after a resume show that job under a new session ID. The latest `--settings` value goes to `$HOME/claude-settings.last`.
  - `stubs/wt` fakes Worktrunk's `switch` and `remove` the way `crew` calls them: it makes real git worktrees, stands in for pre-start and pre-remove hooks (`$HOME/wt-hooks.log`), and logs calls to `$HOME/wt-calls.log`. Touch `$HOME/wt-unapproved`, `wt-elsewhere` or `wt-hook-fail` to simulate unapproved hooks, a branch checked out elsewhere, or a failing hook. Write a script to `$HOME/wt-hook-cmd` and both stand-in hooks run it.
  - `stubs/gh` serves one fake PR (#12) with a fixed set of reviews, inline and conversation comments; the IDs are documented in the file. Looking up an unknown comment or review fails like a 404, and the body of the latest post goes to `$HOME/gh-last-body`. Every PR reads as merged unless `$HOME/gh-pr-state` names another state (`OPEN`). `repo create NAME --private --source . --remote origin` makes a bare repo at `$HOME/remotes/NAME.git` and adds it as `origin`.
  - `stubs/systemctl` logs every call to `$HOME/systemctl-calls.log`, so the tests never touch your real user systemd. `enable` adds units to `$HOME/systemctl-enabled`, which `is-enabled` reads, and `show UNIT -p Environment --value` prints the `Environment=` settings of the installed unit and its drop-ins.

## Adding tests

- Every bug fix gets a case that fails without the fix. Every behaviour change updates the relevant table.
- Use `check "description" 'bash expression'`. The expression is `eval`'d, so single-quote it, and add `# shellcheck disable=SC2034` for variables that only appear inside checks.
- Don't pipe into `grep -q` inside a check while `pipefail` is on: the writer gets SIGPIPE and the check fails. Capture the output into a variable first.
- Never call the real `claude` for a model session, and never point a test at your real `HOME`.
- Check that a new test can fail: break the code briefly and watch it go red.
